# 规则引擎 & 意图路由

## 概述

本项目采用**规则引擎 + 缓存**的方式实现意图识别和路由分发，相比纯 LLM 方案具有更高的性能和确定性。

### 核心优势

| 维度 | 纯 LLM | 规则引擎 |
|------|--------|----------|
| 响应速度 | ~500ms | ~5ms |
| 成本 | 每次调用 LLM | 几乎为 0 |
| 确定性 | 不稳定 | 精确匹配 |
| 可解释性 | 黑盒 | 日志清晰 |
| 可维护性 | 改 prompt | 改规则 |

## 核心组件

### 1. IntentRule (规则定义)

**位置**: `src/main/java/org/fb/engine/IntentRule.java`

```java
@Slf4j
@Getter
public class IntentRule {
    private final String intent;           // 意图类型
    private final List<Pattern> patterns; // 匹配模式(OR逻辑)
    private final int priority;           // 优先级(越小越高)
    private final String description;      // 规则描述
}
```

**核心方法**:
- `matches(message)`: 检查消息是否匹配规则（任一模式匹配即返回true）
- `of(...)`: 静态工厂方法，支持多种创建方式

### 2. IntentRecognitionEngine (规则引擎)

**位置**: `src/main/java/org/fb/engine/IntentRecognitionEngine.java`

**主要功能**:
- 规则初始化与优先级排序
- 缓存机制（避免重复匹配）
- 规则匹配与二次优化
- RAG 检索判断

**核心方法**:
- `recognize(message)`: 意图识别入口（带缓存）
- `doRecognize(message)`: 执行规则匹配
- `shouldRetrieve(intent)`: 判断是否需要 RAG 检索
- `clearCache()`: 清空缓存

### 3. BusinessConstant (意图类型常量)

**位置**: `src/main/java/org/fb/constant/BusinessConstant.java`


## 路由分发逻辑

### StreamingDispatchService

**位置**: `src/main/java/org/fb/service/StreamingDispatchService.java`

```java
public Flux<String> chat(Long memoryId, String userMessage) {
    // 第一步：使用规则引擎进行意图识别
    String intent = intentRecognitionEngine.recognize(userMessage);
    log.info("规则引擎意图识别完成, intent: {}", intent);

    // 第二步：根据意图选择业务处理服务
    if (BusinessConstant.RAG_RETRIEVAL_TYPE.equals(intent)) {
        return processWithRAG(memoryId, userMessage, shouldRetrieve);
    } else if (BusinessConstant.MEDICAL_TYPE.equals(intent)) {
        return processWithDoctorAgent(memoryId, userMessage);
    } else if (BusinessConstant.TRANSLATION_TYPE.equals(intent)) {
        return processWithTranslaterService(memoryId, userMessage);
    } else if (BusinessConstant.TERM_EXTRACTION_TYPE.equals(intent)) {
        return processWithTermExtractionAgent(userMessage);
    } else if (BusinessConstant.SQL_OPERATION_TYPE.equals(intent)) {
        return processWithNaturalLanguageSQLAgent(userMessage);
    } else {
        return chatAssistantStream.chat(memoryId, userMessage);
    }
}
```

### 服务映射

| 意图类型 | 处理服务 | 描述 |
|----------|----------|------|
| rag_retrieval | `ChatAssistantStream` | 启用 RAG 检索 + tools |
| medical | `DoctorAgent` | 医疗助手 |
| translation | `TranslaterService` | 翻译服务 |
| term_extraction | `TermExtractionAgent` | 术语提取 |
| sql_transfer | `NL2SQLService` | 自然语言 SQL |
| general | `ChatAssistantStream` | 默认通用 |

## 缓存机制

### 实现

```java
private final Map<String, String> intentCache = new ConcurrentHashMap<>();
private static final int CACHE_MAX_SIZE = 10000;
```

### 特性

- **线程安全**: 使用 ConcurrentHashMap
- **大小限制**: 最大 10000 条
- **命中条件**: 完全匹配的消息（trim后）
- **用途**: 避免重复匹配相同消息

### 缓存操作

```java
// 读取
String cachedIntent = intentCache.get(trimmedMessage);

// 写入
if (intentCache.size() < CACHE_MAX_SIZE) {
    intentCache.put(trimmedMessage, intent);
}

// 清空
intentCache.clear();
```

## 扩展指南

1. **在 BusinessConstant 中添加常量**:
```java

```

```java

    List.of(
        "关键词1|关键词2",
        "关键词3.*"
    ),
    "新意图描述"
)
```

3. **在 StreamingDispatchService.chat() 中添加处理逻辑**:
```java
if (BusinessConstant.NEW_TYPE.equals(intent)) {
    return processWithNewService(...);
```

### 调整规则

- **修改优先级**: 调整 `priority` 参数
- **添加关键词**: 在 `List.of()` 中添加正则表达式
- **排除误匹配**: 使用负向前瞻 `(?!...)`

## 常见问题

### Q: 为什么"如何设计数据库缓存"被识别为 general 而不是 sql_transfer？

A: 这是**设计意图**。规则引擎的 sql_transfer 只匹配**明确的数据库查询请求**（如"查询用户表"），而"如何设计..."是**概念/知识类问题**，应该由 general 处理，直接用通用知识回答。

### Q: 规则引擎能否完全替代 LLM 意图识别？

A: 目前采用**规则引擎优先 + 可扩展 LLM 兜底**的策略。`needsLLMFallback()` 方法预留了扩展点，当前返回 false 表示完全信任规则引擎。

### Q: 如何调试规则匹配？

A: 查看日志中的 `匹配到规则` 和 `消息匹配规则` DEBUG 日志，可以清晰看到匹配过程。
