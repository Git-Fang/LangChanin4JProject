# 多模型动态切换实现文档

## 概述

本文档描述项目中多模型动态切换的实现架构。该功能允许在运行时根据用户选择动态切换不同的AI模型（如通义千问、DeepSeek、Ollama、Kimi等），而不需要重启服务。

## 核心组件

### 1. ModelRegistry（模型注册表）

**位置**: `org.fb.config.ModelRegistry`

**职责**:
- 管理所有可用AI模型的元信息
- 维护模型的启用/禁用状态
- 提供模型可用性检查

**支持模型**:
| modelId | displayName | provider | 说明 |
|---------|-------------|----------|------|
| qwen | 通义千问 | 阿里云 | 默认模型，需配置DashScope API Key |
| deepseek | DeepSeek | DeepSeek | 需配置DeepSeek API Key |
| ollama | Ollama (本地) | Ollama | 本地模型，无需API Key |
| kimi | Kimi | 月之暗面 | 需配置Kimi API Key |

**关键方法**:
```java
// 获取所有可用模型
List<ChatModelInfo> getAvailableModels();

// 检查模型是否可用
boolean isModelAvailable(String modelId);

// 获取默认模型ID
String getDefaultModelId();

// 动态启用/禁用模型
void setModelEnabled(String modelId, boolean enabled);
```

### 2. DynamicStreamingChatModel（动态流式模型代理）

**位置**: `org.fb.config.DynamicStreamingChatModel`

**职责**:
- 代理多个底层 StreamingChatModel 实现
- 运行时动态切换当前使用的模型
- 实现 StreamingChatModel 接口

**核心逻辑**:
```java
public class DynamicStreamingChatModel implements StreamingChatModel {
    private final Map<String, StreamingChatModel> models = new ConcurrentHashMap<>();
    private volatile String currentModelId = "qwen"; // 默认模型
    
    // 注册模型
    public void registerModel(String modelId, StreamingChatModel model)
    
    // 设置当前模型
    public void setCurrentModel(String modelId)
    
    // 获取当前模型
    private StreamingChatModel getCurrentModel()
    
    // 处理聊天请求
    @Override
    public void chat(ChatRequest chatRequest, StreamingChatResponseHandler handler) {
        log.info("【动态模型】chat() 调用, modelId={}", currentModelId);
        StreamingChatModel model = getCurrentModel();
        model.chat(chatRequest, handler);
    }
}
```

### 3. LLMConfig（模型配置与初始化）

**位置**: `org.fb.config.LLMConfig`

**职责**:
- 在应用启动时初始化所有AI模型
- 将各模型注册到 DynamicStreamingChatModel

**初始化流程**:
```java
@PostConstruct
public void init() {
    refreshAllModels();
}

private void refreshDynamicStreamingChatModel() {
    this.dynamicStreamingChatModel = new DynamicStreamingChatModel();
    
    // 注册各模型
    if (streamingChatModel != null) {
        dynamicStreamingChatModel.registerModel("qwen", streamingChatModel);
    }
    if (deepSeekStreamingChatModel != null) {
        dynamicStreamingChatModel.registerModel("deepseek", deepSeekStreamingChatModel);
    }
    if (ollamaStreamingChatModel != null) {
        dynamicStreamingChatModel.registerModel("ollama", ollamaStreamingChatModel);
    }
    if (kimiStreamingChatModel != null) {
        dynamicStreamingChatModel.registerModel("kimi", kimiStreamingChatModel);
    }
    
    // 设置默认模型
    dynamicStreamingChatModel.setCurrentModel("qwen");
}
```

### 4. StreamingDispatchService（流式分发服务）

**位置**: `org.fb.service.StreamingDispatchService`

**职责**:
- 解析并验证模型ID
- 设置 DynamicStreamingChatModel 的当前模型
- 根据意图识别选择业务处理服务

**模型解析流程**:
```java
private String resolveModelId(String modelId) {
    if (modelRegistry == null) {
        return null; // ModelRegistry未注入，使用默认
    }
    
    if (modelId == null || modelId.isEmpty()) {
        return modelRegistry.getDefaultModelId();
    }
    
    if (!modelRegistry.isModelAvailable(modelId)) {
        log.warn("【模型解析】指定的模型 {} 不可用，切换到默认模型", modelId);
        return modelRegistry.getDefaultModelId();
    }
    
    return modelId;
}
```

## 完整调用流程

### HTTP流式聊天流程 (unified.html)

```
1. 用户在前端选择模型 (currentModelId)
                   │
                   ▼
2. 前端发送 POST /xiaozhi/chat/http-stream
   {
     "memoryId": 123,
     "message": "你好",
     "modelId": "kimi"   // ← 用户选择的模型
   }
                   │
                   ▼
3. AsyncChatController.startHttpStreamChat()
   - 获取 chatForm.getModelId() = "kimi"
   - 创建 ChatRequestMessage，modelId 存入 metadata
   - 保存到 Redis (key: chat:request:{requestId})
   - 返回 { requestId, streamUrl: "/xiaozhi/chat/http-stream/{requestId}" }
                   │
                   ▼
4. 前端发起 GET /xiaozhi/chat/http-stream/{requestId}
                   │
                   ▼
5. AsyncChatController.streamHttpChat()
   - 从 Redis 获取请求数据
   - 提取 modelId = request.getMetadata().getModelId()
   - 调用 streamingDispatchService.chat(memoryId, message, modelId)
                   │
                   ▼
6. StreamingDispatchService.chat()
   - resolveModelId(modelId) 验证模型可用性
   - dynamicStreamingChatModel.setCurrentModel("kimi")
   - 选择业务服务处理请求
                   │
                   ▼
7. DynamicStreamingChatModel.chat()
   - log.info("【动态模型】chat() 调用, modelId=kimi")
   - 获取 models.get("kimi") = kimiStreamingChatModel
   - 调用底层模型的 chat() 方法
                   │
                   ▼
8. SSE流式返回给前端
```

## 注意事项

1. **模型注册时机**: 所有模型在应用启动时通过 `@PostConstruct` 初始化，只有配置了有效API Key的模型才会被注册

2. **模型可用性检查**: 
   - 前端传来的 modelId 会经过 `ModelRegistry.isModelAvailable()` 验证
   - 不可用的模型会自动回退到默认模型(qwen)

3. **线程安全**: 
   - `DynamicStreamingChatModel` 使用 `volatile` 修饰 `currentModelId`
   - 使用 `ConcurrentHashMap` 存储模型映射

4. **日志追踪**: 
   - 通过日志可以追踪完整的模型切换流程
   - 关键日志前缀: `【动态模型】`、`【模型切换】`、`【模型解析】`

5. **缓存清理**: 
   - 模型切换时可调用 `DynamicAiServiceFactory.clearCache(modelId)` 清理缓存
