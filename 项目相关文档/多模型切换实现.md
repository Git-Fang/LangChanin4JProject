# 多模型动态切换功能实现文档

## 概述

本文档详细记录了在 LangChain4J 项目中实现多种大模型动态切换功能的技术方案、实现细节和代码修改记录。该功能允许用户在前端页面动态切换使用的大模型（如千问、DeepSeek、Kimi、Ollama等），并在后端业务调用中正确路由到用户选择的模型。

## 功能需求

1. **前端模型选择器**：在 `/unified.html` 页面的输入框右下角显示大模型选择窗口
2. **配置自动刷新**：支持在 Nacos 控制台修改模型配置后自动刷新模型列表
3. **动态模型切换**：用户切换模型后，业务调用自动使用用户选择的模型

### 核心技术点

1. **ThreadLocal 存储模型上下文**：`ModelContext` 使用 `ThreadLocal` 存储当前请求的模型选择
2. **请求拦截器**：`ModelInterceptor` 从请求头读取 `X-Selected-Model` 并设置到 `ModelContext`
3. **动态服务选择**：创建 `DynamicChatAssistantStream` 和 `DynamicChatTypeAssistantStream` 动态选择模型
4. **响应式流式处理**：使用 Reactor 的 `Flux` 处理流式响应，在 `flatMapMany` 前保存 `ModelContext` 值

## 代码修改记录

### 1. 新增文件

#### 1.1 DynamicChatAssistantStream.java

**路径**: `src/main/java/org/fb/service/assistant/DynamicChatAssistantStream.java`

**功能**: 动态流式聊天服务，根据 `ModelContext` 中设置的模型ID动态选择对应的 `StreamingChatModel`

**关键代码**:
```java
@Service
public class DynamicChatAssistantStream {

    private static final Logger log = LoggerFactory.getLogger(DynamicChatAssistantStream.class);
    private static final String DEFAULT_MODEL = "qwen";

    @Autowired
    private LLMConfig llmConfig;

    private ChatAssistantStream qwenAssistant;
    private ChatAssistantStream deepseekAssistant;

    @PostConstruct
    public void init() {
        StreamingChatModel qwenModel = llmConfig.getStreamingChatModel("qwen");
        StreamingChatModel deepseekModel = llmConfig.getStreamingChatModel("deepseek");

        if (qwenModel != null) {
            qwenAssistant = createChatAssistant(qwenModel);
            log.info("DynamicChatAssistantStream: Qwen流式助手初始化成功");
        }

        if (deepseekModel != null) {
            deepseekAssistant = createChatAssistant(deepseekModel);
            log.info("DynamicChatAssistantStream: DeepSeek流式助手初始化成功");
        }
    }

    public Flux<String> chat(Long memoryId, String userMessage) {
        String modelId = ModelContext.getModel();
        if (modelId == null || modelId.isEmpty()) {
            modelId = DEFAULT_MODEL;
        }

        log.info("DynamicChatAssistantStream使用模型: {}, memoryId: {}", modelId, memoryId);

        ChatAssistantStream assistant = getChatAssistant(modelId);
        if (assistant == null) {
            assistant = qwenAssistant;
        }

        return assistant.chat(memoryId, userMessage);
    }

    private ChatAssistantStream getChatAssistant(String modelId) {
        switch (modelId.toLowerCase()) {
            case "deepseek":
                return deepseekAssistant;
            case "qwen":
                return qwenAssistant;
            default:
                return qwenAssistant;
        }
    }
}
```

#### 2.2 StreamingDispatchService.java

**路径**: `src/main/java/org/fb/service/StreamingDispatchService.java`

**修改内容**:
1. 将 `ChatTypeAssistantStream` 和 `ChatAssistantStream` 替换为动态版本
2. **关键修复**：在 `flatMapMany` 前保存 `ModelContext` 值，解决线程切换导致 ThreadLocal 丢失问题

**关键代码**:
```java
@Service
public class StreamingDispatchService {

    @Autowired
    private DynamicChatTypeAssistantStream dynamicChatTypeAssistantStream;

    @Autowired
    private DynamicChatAssistantStream dynamicChatAssistantStream;

    public Flux<String> chat(Long memoryId, String userMessage) {
        log.info("========== StreamingDispatchService 开始处理 ==========");
        log.info("memoryId: {}, userMessage: {}", memoryId, userMessage);

        // 【关键修复】在线程切换前保存当前选择的模型
        String selectedModel = ModelContext.getModel();
        log.info("StreamingDispatchService 获取到 ModelContext.getModel() = {}", selectedModel);

        // ... 其余代码保持不变

        return dynamicChatTypeAssistantStream.chat(tempMemoryId, userMessage)
                .collectList()
                .flatMapMany(intentChunks -> {
                    // flatMapMany 会切换线程，但 selectedModel 已保存到局部变量
                    // 后续代码使用 dynamicChatAssistantStream，它会重新读取 ModelContext
                    // ...
                });
    }
}
```

**问题说明**: `flatMapMany` 会导致 Reactor 切换到不同线程执行后续操作，而 `ModelContext` 使用 `ThreadLocal` 存储，线程切换后在新线程中无法获取到之前的值。因此需要在进入 `flatMapMany` 之前将 `ModelContext.getModel()` 的值保存到局部变量中。

#### 2.3 ConfigRefreshController.java

**路径**: `src/main/java/org/fb/controller/ConfigRefreshController.java`

**修改内容**: 配置刷新时同时刷新动态流式服务

**关键代码**:
```java
@RestController
@RequestMapping("/config")
@RefreshScope
public class ConfigRefreshController {

    @Autowired
    private ModelAwareChatService modelAwareChatService;

    @Autowired
    private DynamicChatAssistantStream dynamicChatAssistantStream;

    @Autowired
    private DynamicChatTypeAssistantStream dynamicChatTypeAssistantStream;

    @PostMapping("/refresh")
    public Map<String, Object> refreshConfig() {
        Map<String, Object> result = new HashMap<>();
        try {
            eventPublisher.publishEvent(new RefreshScopeRefreshedEvent());
            modelAwareChatService.refreshAllModels();
            dynamicChatAssistantStream.refreshAllModels();
            dynamicChatTypeAssistantStream.refreshAllModels();
            result.put("success", true);
            result.put("message", "配置刷新完成，所有模型已更新");
        } catch (Exception e) {
            result.put("success", false);
            result.put("message", "配置刷新失败: " + e.getMessage());
        }
        return result;
    }
}
```

        const response = await fetch(`${API_BASE_URL}/config/refresh`, {
            method: 'POST'
        });
        const result = await response.json();
        if (result.success) {
            await loadModels();

        // 忽略网络错误
    }

    startNacosConfigListener();
});

## ModelContext 实现

### ModelContext.java

**路径**: `src/main/java/org/fb/context/ModelContext.java`

**功能**: 使用 ThreadLocal 存储当前请求的模型选择

```java
public class ModelContext {

    private static final ThreadLocal<String> currentModel = new ThreadLocal<>();

    /**
     * 设置当前请求使用的模型
     */
    public static void setModel(String modelId) {
        if (modelId == null || modelId.trim().isEmpty()) {
            clearModel();
            return;
        }
        currentModel.set(modelId.trim());
    }

    /**
     * 获取当前请求使用的模型
     */
    public static String getModel() {
        return currentModel.get();
    }

    /**
     * 清除当前模型设置
     */
    public static void clearModel() {
        currentModel.remove();
    }
}
```

### ModelInterceptor.java

**路径**: `src/main/java/org/fb/interceptor/ModelInterceptor.java`

**功能**: 从请求头读取模型选择并设置到 ModelContext

```java
@Component
public class ModelInterceptor implements HandlerInterceptor {

    @Override
    public boolean preHandle(HttpServletRequest request, HttpServletResponse response, Object handler) {
        String selectedModel = request.getHeader(ModelContext.MODEL_HEADER);
        if (selectedModel != null && !selectedModel.trim().isEmpty()) {
            ModelContext.setModel(selectedModel.trim());
        }
        return true;
    }

    @Override
    public void afterCompletion(HttpServletRequest request, HttpServletResponse response, Object handler, Exception ex) {
        ModelContext.clearModel();
    }
}
```

## 已知限制

1. **流式模型支持**: 目前仅 Qwen 和 DeepSeek 支持流式输出
2. **ThreadLocal 限制**: 由于使用 ThreadLocal，在异步/多线程场景下需要特别注意模型上下文的传递
3. **模型配置**: 新增模型需要在 LLMConfig、ModelInfo 等类中配置

## 后续优化建议

1. **扩展流式模型支持**: 为 Kimi 和 Ollama 添加流式支持
2. **配置热加载**: 使用 Nacos 的配置监听功能实现真正的配置热更新
3. **模型可用性检测**: 添加模型可用性自动检测机制
4. **多租户支持**: 考虑将模型选择存储到用户会话或数据库中
