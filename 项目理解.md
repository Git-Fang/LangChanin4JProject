# RAGTranslation4 项目理解文档

## 1. 项目概述

### 1.1 项目简介

**RAGTranslation4** 是一个基于 **LangChain4j + Spring AI** 的多模态 AI 对话与 RAG（检索增强生成）服务系统。该项目旨在提供一个智能对话平台，支持多种 AI 模型、多场景业务处理、完整的 RAG 知识检索能力以及完善的监控体系。

### 1.2 项目定位

- **核心定位**：企业级 AI 对话服务平台
- **业务场景**：智能客服、医疗咨询、翻译服务、自然语言数据库查询、术语提取
- **技术特点**：多模型支持、流式输出、RAG 知识库、微服务架构

### 1.3 版本与技术栈

| 项目 | 版本/信息 |
|------|----------|
| 项目名称 | RAGTranslation4 |
| 项目分组 | org.fb |
| 核心框架 | Spring Boot 3.5.0 |
| Java 版本 | 17 |
| 构建工具 | Maven |
| 部署方式 | Docker 容器化 |

## 4. 核心业务流程

### 4.1 整体请求处理流程

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                           整体请求处理流程                                    │
└─────────────────────────────────────────────────────────────────────────────┘

用户请求 (/xiaozhi/chat)
       │
       ▼
┌─────────────────────────────────────────────────────────────┐
│                      1. 意图识别层                           │
│              ChatTypeAssistant / ChatTypeAssistantStream     │
│              使用 LLM 理解用户意图，判断业务类型               │
└─────────────────────────────────────────────────────────────┘
       │
       ▼
┌─────────────────────────────────────────────────────────────┐
│                      2. 意图分发层                           │
│    根据识别的 intent 类型，选择对应的业务处理服务：           │
│                                                              │
│    • medical (医疗)        → DoctorAgent                    │
│    • translation (翻译)    → TranslaterService              │
│    • term_extraction       → TermExtractionAgent            │
│    • sql_transfer (SQL)    → NL2SQLService                  │
│    • default (通用)        → ChatAssistant                  │
└─────────────────────────────────────────────────────────────┘
       │
       ▼
┌─────────────────────────────────────────────────────────────┐
│                      3. 业务处理层                           │
│    各业务 Agent 处理具体请求：                               │
│                                                              │
│    • 调用 RAG 知识检索 (Qdrant 向量库)                       │
│    • 获取对话历史 (MongoDB ChatMemory)                      │
│    • 执行工具调用 (如数据库查询、翻译等)                      │
│    • 调用 LLM 生成回复                                      │
└─────────────────────────────────────────────────────────────┘
       │
       ▼
┌─────────────────────────────────────────────────────────────┐
│                      4. 结果返回层                           │
│    根据请求类型选择返回方式：                                │
│                                                              │
│    • 同步 HTTP 响应                                         │
│    • SSE 流式推送 (Server-Sent Events)                      │
│    • Kafka + SSE (高并发场景)                               │
└─────────────────────────────────────────────────────────────┘
```

### 4.3 核心服务实现

#### 4.3.1 ChatServiceImpl（同步模式）

**位置**：`src/main/java/org/fb/service/impl/ChatServiceImpl.java`

**核心方法**：
```java
public String chat(Long memoryId, String message) {
    // 1. 意图识别
    String intent = processByUserMeanings(memoryId, message);

    // 2. 根据意图路由到对应的 Agent
    switch (intent) {
        case "medical": return doctorAgent.chat(memoryId, userMessage);
        case "translation": return translaterService.translate(memoryId, actualTextToTranslate);
        case "term_extraction": return termExtractionAgent.chat(userMessage);
        case "sql_transfer": return nl2SQLService.executeNaturalLanguageQuery(userMessage);
        default: return chatAssistant.chat(memoryId, userMessage);
    }
}
```

#### 4.3.2 StreamingDispatchService（流式模式）

**位置**：`src/main/java/org/fb/service/StreamingDispatchService.java`

**核心方法**：
```java
public Flux<String> chat(Long memoryId, String userMessage) {
    return chatTypeAssistantStream.chat(tempMemoryId, userMessage)
        .collectList()
        .flatMapMany(intentChunks -> {
            String intent = extractIntent(String.join("", intentChunks));

            // 根据意图选择业务处理服务
            Flux<String> resultFlux;
            if ("medical".equals(intent)) {
                resultFlux = processWithDoctorAgent(memoryId, userMessage);
            } else if ("translation".equals(intent)) {
                resultFlux = processWithTranslaterService(memoryId, userMessage);
            } else if ("term_extraction".equals(intent)) {
                resultFlux = processWithTermExtractionAgent(userMessage);
            } else if ("sql_transfer".equals(intent)) {
                resultFlux = processWithNaturalLanguageSQLAgent(userMessage);
            } else {
                resultFlux = chatAssistantStream.chat(memoryId, userMessage);
            }
            return resultFlux;
        });
}
```

#### 4.3.3 NL2SQLService（自然语言转 SQL）

**位置**：`src/main/java/org/fb/service/impl/NL2SQLService.java`

**核心功能**：
- 将自然语言转换为 SQL 查询语句
- SQL 安全验证（只读操作、危险操作拦截）
- 数据库元信息获取
- 查询结果格式化

```java
public List<Map<String, Object>> executeNaturalLanguageQuery(String naturalLanguage) {
    // 1. 获取数据库 Schema 信息
    String schemaInfo = getDatabaseSchema();

    // 2. 构建提示词并调用 LLM 生成 SQL
    String sql = naturalLanguageToSQL(schemaInfo, naturalLanguage);

    // 3. 验证 SQL 合法性
    validateSQL(sql);

    // 4. 执行 SQL 查询
    return jdbcTemplate.queryForList(sql);
}
```

## 7. 流式输出架构

### 7.1 三种流式输出模式

| 模式 | 前端页面 | 协议 | 适用场景 |
|------|---------|------|---------|
| **HTTP 流式输出** | unified.html (HTTP模式) | POST + SSE | 简单的一问一答场景 |
| **SSE 实时聊天** | chat-sse.html | Kafka + SSE | 高并发、需要消息队列解耦的场景 |
| **MCP SSE 模式** | unified.html (SSE模式) | JSON-RPC 2.0 + SSE | 需要调用外部工具的场景 |

### 7.2 HTTP 流式输出模式

**接口**：`POST /xiaozhi/chat/http-stream`

**流程**：
```
1. POST 提交请求 → 返回 requestId 和 streamUrl
2. GET 请求 streamUrl → 建立 SSE 连接
3. SSE 推送内容块 (chunk)、结果 (result)、完成 (complete)
```

### 7.3 SSE 实时聊天模式（Kafka + SSE）

**接口**：`POST /xiaozhi/chat/async`

**流程**：
```
1. POST 提交请求 → 发送到 Kafka 消息队列 → 返回 requestId
2. Kafka 消费者异步处理消息 → 结果存入 Redis
3. 前端建立 SSE 连接 → 轮询 Redis 获取结果 → SSE 推送
```

### 7.4 MCP SSE 模式

**接口**：`GET /mcp/sse?sessionId={sessionId}`

**协议**：JSON-RPC 2.0

**支持的方法**：
- `initialize`：初始化连接
- `tools/list`：获取工具列表
- `tools/call`：调用工具

## 17. 文档摘要总结服务

### 17.1 功能概述

文档概要摘要服务是项目的核心功能模块之一，提供对上传文档进行**语义切分**和**智能摘要**的完整解决方案。该服务支持多种文档格式，能够自动识别文档结构，按语义边界进行切片，并为每个切片生成精炼的摘要内容。

**核心价值**：
- 将长文档自动拆分为语义完整的片段
- 每个片段生成150字以内的精炼摘要
- 摘要内容自动存储到Qdrant向量数据库，支持后续RAG检索
- 支持批量并行处理，提高处理效率

### 17.2 核心组件

| 组件 | 位置 | 功能说明 |
|------|------|----------|
| `SummaryChunk` | `bean/SummaryChunk.java` | 摘要结果实体类，包含文章标题、摘要、内容、切片序号等字段 |
| `DocumentSummarizationService` | `service/DocumentSummarizationService.java` | 摘要服务接口，定义核心业务方法 |
| `DocumentSummarizationServiceImpl` | `service/impl/DocumentSummarizationServiceImpl.java` | 摘要服务实现，核心业务逻辑 |
| `DocumentSummarizationController` | `controller/DocumentSummarizationController.java` | REST API控制器，提供HTTP接口 |

### 17.3 API 接口

#### 17.3.1 单文档摘要

### 17.5 语义切分算法

**切分策略**（`semanticChunking`方法）：

```
输入: 原始文本
输出: 切分后的文本片段列表

1. 按段落分割（按换行符拆分）
2. 遍历每个段落，构建切片：
   - 如果当前切片为空，直接添加段落
   - 如果添加段落会超过1024字符限制：
     a. 如果当前切片 >= 1024 * 0.7，按句号进一步切分
     b. 否则直接保存当前切片，开始新切片
3. 处理最后一个切片
4. 返回所有切片列表
```

**按句号切分策略**（`splitBySentenceWithLimit`方法）：

```
输入: 待切分文本，最大长度限制
输出: 切分后的句子列表

1. 使用正则表达式匹配句号分割符：[。！？.!?]
2. 提取所有完整句子
3. 组合句子到当前块：
   - 如果单个句子超限，强制按字符数切分
   - 如果添加句子会超限，保存当前块，开始新块
4. 处理最后一个块
```

### 17.6 摘要生成逻辑

**提示词模板**（可配置，默认模板）：

```
请为以下文本生成一段150字以内的精炼中文摘要。

要求：
1. 严格控制在150字以内
2. 突出核心信息，去除冗余表达
3. 保留关键数据、名词和动词
4. 句意完整，不截断句子
5. 只输出摘要内容，不要任何解释说明

文本内容：
{{content}}
```

**摘要生成流程**（`generateSummary`方法）：

```
1. 替换提示词模板中的{{content}}占位符
2. 调用LLM生成摘要
3. 清理输出：
   - 去除首尾空白
   - 去除可能的引号包裹
   - 移除残留的引号字符
4. 截断到150字，超长部分用"..."省略
```
